# JobFit Agent 正式岗位知识来源政策

## 1. 目的与适用范围

本政策用于 JobFit Agent v1.1.0 首批正式岗位知识的来源准入、分级、交叉验证、版权处理和失效管理。首批范围仅包括：

- AI 应用实习生；
- 数据分析实习生；
- 技术战略实习生。

产品分析实习生延后至 v1.1.x。本政策约束公开仓库中的来源元数据和原创知识归纳，不授权保存第三方网页完整副本，也不允许把岗位知识解释为候选人事实或评分依据。

## 2. 核心原则

1. 每个来源必须由研究者实际打开原页面核验；搜索结果摘要只能用于发现线索。
2. 公开可访问不等于可以自由复制。仓库只保存必要元数据、短引用和原创归纳。
3. 知识来源解释岗位；简历原文证据判断候选人。两类证据不得混用。
4. 知识条目的可靠性等级不改变匹配分、评分权重、hard blocker 或推荐等级。
5. 单个企业的岗位描述不能代表整个职业方向；企业特有工具必须与通用能力分开。
6. 未出现在本次 JD 中的知识要求不得进入评分分母，也不得自动升级为本次 JD 的硬门槛。
7. 只有 `approved` 条目和 `published` 知识版本可用于正式分析。
8. 无法确认发布主体、访问状态或使用边界的来源不得支撑正式核心要求。

## 3. 来源等级

### 3.1 A 级：优先来源

- 企业官方招聘、人才或技术页面；
- 政府职业标准和官方职业分类；
- 官方行业组织或标准机构；
- 官方技术文档；
- 发布主体明确、公开可访问的正式研究报告。

A 级来源通常映射为 `primary` 或 `high`，但来源等级与系统的 `reliability_level` 不是机械一一对应：一个官方页面若只描述单一企业情境，仍需限制其适用范围。

### 3.2 B 级：补充来源

- 高质量大学职业发展资料；
- 知名研究机构公开报告；
- 企业官方演讲、技术文章或教育资料；
- 有明确作者、日期和依据的专业文章。

B 级来源通常映射为 `high` 或 `medium`，用于补充能力解释、研究方法和相邻岗位边界。

### 3.3 C 级：仅作线索

- 招聘平台页面；
- 行业媒体；
- 个人经验文章；
- 社区讨论；
- 搜索结果摘要。

C 级来源不能单独支撑 `must_have`、`critical` 或通用核心要求。若最终采用，必须有 A 级来源或至少两个相互独立的 B 级来源交叉验证。

### 3.4 禁止来源

- 无作者、无发布主体或正文来源不一致的转载；
- 内容农场、自动生成文章和无法打开的页面；
- 明显过时、已撤销且无法确认历史状态的材料；
- 需绕过登录、付费、验证码或访问限制的内容；
- 企业内部资料、客户资料和未经授权的真实 JD；
- 含歧视性岗位要求或违法收集个人信息的材料。

## 4. 系统枚举映射

正式 Seed 必须使用现有枚举，不另造一套值：

| 内容概念 | Seed 值 |
| --- | --- |
| 官方岗位描述 | `official_job_description` |
| 公开招聘或人才页面 | `public_recruitment_page` |
| 官方能力定义、职业标准或技术方法 | `expert_definition` |
| 项目原创模板 | `internal_template` |
| 正式研究报告 | `research_report` |
| 原始一手来源 | `primary` |
| 高可靠来源 | `high` |
| 中等可靠来源 | `medium` |
| 低可靠线索 | `low` |

`primary` 仅用于发布主体直接发布的岗位、标准或原始材料；它不表示内容自动适用于所有企业。

## 5. 准入门禁

每个候选来源必须记录并审核：

- 稳定 `source_id`；
- 岗位方向和适用地区；
- 页面标题与发布主体；
- 与 Schema 兼容的 `source_type`；
- 实际打开过的 HTTP(S) URL；
- 可确认的发布日期；无法确认时明确写“未确认”；
- 本次访问日期；
- 来源等级和 `reliability_level`；
- 可支撑的知识类别；
- `license_note`；
- 是否允许短摘要、是否适合写入公开仓库；
- 页面易失风险和存档元数据要求；
- `pending`、`approved` 或 `rejected` 审核状态。

以下任一情况发生时不得批准：

- URL 未实际打开；
- 页面标题、发布主体或正文无法对应；
- 用搜索摘要替代原页面核验；
- 猜测发布日期、许可证或作者；
- 需要复制大段原文才能表达知识；
- 仅凭单一低可靠来源形成核心要求；
- 内容无法保持岗位边界或实习生层级。

## 6. 来源多样性与交叉验证

每个岗位方向采用 5—8 个高质量来源，并满足：

1. 同一企业来源原则上不超过该岗位来源总数的 30%。
2. 每个岗位至少包含两个企业一手岗位或人才来源，以及两个职业、技术或研究框架来源；若个别岗位缺少合适企业来源，应记录不足，不以弱来源凑数。
3. 通用核心要求需要两个独立来源支持，或一个具有直接规范效力的高权威官方标准支持。
4. 同一集团、转载链或引用同一原始材料的页面不视为独立来源。
5. 企业特有工具只可写为示例关键词或企业情境，不可直接写成通用要求。
6. 时间敏感的模型、平台和工具必须记录核验日期；底层能力与具体产品名称分开表达。
7. 不同国家或地区的职业标准需标注适用范围，不直接外推为全球统一要求。
8. 核心能力与相邻岗位边界应同时被验证，避免把数据工程、纯算法研究、投资研究等内容混入目标岗位。

## 7. 版权与使用规则

### 7.1 可以保存

- 页面标题、发布主体、URL、日期和访问状态；
- 必要的短引用，且受现有字段长度和引用规范限制；
- 对来源内容的原创归纳；
- 适用范围、版本、许可证和版权备注；
- 为可追溯性计算的 checksum，不保存完整网页副本。

### 7.2 不得保存

- 完整招聘页面、完整 JD 或大段连续原文；
- 付费报告正文或通过访问限制获得的内容；
- 无法确认授权的大段 `chunk_text`；
- 被删除的署名、版权声明或发布主体信息；
- 第三方网页中的指令、脚本、HTML 或 Prompt Injection 文本。

### 7.3 `license_note` 最低内容

`license_note` 必须说明：

- 页面或材料的权利主体；
- 已知许可证或版权状态；
- 本项目保存的内容范围；
- 是否仅保存元数据与原创归纳；
- 若许可证未明确，明确写“未授予再分发许可，仅记录元数据和原创归纳”。

公开访问页面默认采用保守处理：不推定自由再分发。无法确认边界时，只保留来源元数据并维持 `pending`。

## 8. 时效性与失效页面处理

- 每个来源记录 `collected_at`，时间敏感页面还需记录建议复核周期。
- 官方招聘页建议在每次知识版本发布前重新核验；职业标准和研究报告至少在年度版本编制时复核。
- 页面失效后保留其来源记录、最后成功访问日期和失效状态，不把它伪装为当前可用来源。
- 失效来源不能作为新版本唯一支撑；核心条目必须补充可访问来源或降级为 `pending`。
- 不在仓库保存第三方网页镜像。允许保存标题、发布主体、发布日期、访问日期、内容 checksum 和失效原因等存档元数据。
- 页面内容发生实质变化时应创建新的来源记录或更新知识版本，不能仅凭同一 URL 假定内容未变。

## 9. 来源与知识条目映射

- `role_profiles` 通过 `source_role_links` 记录 `supports`、`contrasts` 或 `background` 关系。
- 每条 `role_requirement`、`evidence_pattern`、`interview_question` 和 `knowledge_chunk` 必须引用一个真实、已审核的 `source_id`。
- 一个条目需要多来源支撑时，选择最直接的一手来源作为该条目的 `source_id`，并用额外的来源—画像关系、相邻条目或审核记录保存交叉验证；不在文本字段内拼接伪造的多来源 ID。
- `contrasts` 用于相邻岗位或不适用边界，不能被解释为正向要求。
- `background` 用于趋势、行业背景或方法论，不得单独支撑 `critical` 要求。
- 来源可靠性只影响审核结论和解释，不参与候选人评分。

## 10. 网络研究操作规则

允许人工、低频地打开公开页面核验元数据。禁止自动爬虫、批量下载、绕过登录或验证码，以及把搜索结果摘要当作事实来源。研究记录必须区分：

- 已在访问日期成功打开并核验；
- 页面动态加载但官方元数据可确认；
- 页面失效；
- 发布日期未确认；
- 版权或再分发许可未确认。

任何未确认项必须明确记录，不能用模糊占位符掩盖。

## 11. 发布前来源检查

- [ ] 每个岗位有 5—8 个通过准入审核的来源。
- [ ] 每个 URL 已打开，标题与发布主体一致。
- [ ] 来源等级、`source_type`、`reliability_level` 和适用范围一致。
- [ ] 单一企业占比不超过 30%。
- [ ] 核心要求满足交叉验证规则。
- [ ] 每个来源填写 `license_note`。
- [ ] 未保存完整网页、完整 JD 或付费报告正文。
- [ ] 时间敏感内容记录访问日期和复核要求。
- [ ] 失效页面未被当作当前唯一依据。
- [ ] 所有正式条目只使用 `approved` 来源。
