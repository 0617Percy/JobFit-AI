# 2026.08.1 AI应用实习生知识用户决策表

> 决策记录：2026-08-03。用户确认 D-01 至 D-09 全部采用 Codex 建议，并授权进入 Phase 11.9B1-F。该授权仅用于调整 draft Seed、更新审核记录、复算 Canonical Hash 和执行离线验证；不构成 `approved`、`published`、B2、生产配置修改或运行数据库导入授权。

## A. 总体结论

- **岗位画像**：建议保留 `rp-ai-application-intern` 单一核心画像，并将 Agent、Prompt、AI Solutions 等继续作为应用方向别名；当前内容没有扩张到基础模型研究、纯产品、纯数据或高阶 MLOps。
- **能力维度**：11 个维度均建议保留；含义可区分，`scoring_category_hint` 全部为空，没有映射或改变 ScoringEngine。跨岗位复用应在三岗位内容齐备后统一审查，不在当前 Seed 中提前共用带 `cd-ai-` 前缀的 ID。
- **Requirements**：15 条均属于画像范围，无删除或合并建议；建议 1 条措辞修订、3 条类型降级、3 条 importance 降级。
- **Evidence Patterns**：17 条均建议保留现有强度。强证据强调可验证的实现、控制或复现产物，不要求实习生虚构商业指标；弱证据只表示证据不足，不表示候选人不会。
- **Interview Questions**：10 道均建议保留，覆盖核心能力且为原创问题；建议调整 2 道题的难度。
- **来源**：7 个来源均可继续进入公开 Seed，但必须保持当前限定用途；Google 页面日期字段建议由用户确认是否保留“最后更新日”。
- **版权与安全**：人工比对未发现连续大段原文、企业面试题复制、虚假授权、PII、Prompt Injection 或候选人事实。直接正文引用为 0；页面标题属于来源元数据。
- **发布门禁**：用户已授权 B1-F，并明确不授权 B2、`approved`、`published`、生产配置修改或运行数据库导入。B1-F 完成后，所有正式知识仍保持 `draft/pending`。

## B. 必须由用户决定的事项

### D-01 单一岗位画像

- 涉及 ID：`rp-ai-application-intern`
- 当前内容：一个 AI 应用实习生核心画像，Agent、LLM Application、AI Solutions 等作为有限别名。
- Codex 建议：保留单一画像，子画像延后至 v1.1.x，避免首版召回歧义。
- 可选项：保留单一画像 / 现在拆分子画像 / 修改别名范围。
- 影响：现在拆分会提高 ambiguous 概率，并扩大 B1-F 与后续检索验收范围。
- 用户选择：采用 Codex 建议：保留单一画像，子画像延后至 v1.1.x。

### D-02 跨岗位能力维度复用策略

- 涉及 ID：`cd-ai-business-understanding`、`cd-ai-communication-collaboration`、`cd-ai-data-processing`、`cd-ai-evaluation-debugging`、`cd-ai-responsible-ai-security`
- 当前内容：概念具有跨岗位复用潜力，但 ID 和部分描述明确带 AI 应用语境。
- Codex 建议：本批保留全部 11 个维度及现有 ID；到 B3 三岗位统一审查时再决定抽取通用维度，避免数据分析阶段直接复用 AI 专属语义。
- 可选项：本批保留并延后统一 / B1-F 立即改成全局通用 ID / 后续岗位各自建立专属维度。
- 影响：立即改 ID 会连带修改 requirements、questions、hash 和审核记录；完全复制则可能形成同义维度。
- 用户选择：采用 Codex 建议：本批保留全部 11 个维度和现有 ID，跨岗位通用维度延后至 B3 统一审查。

### D-03 Python 核心实现能力

- 涉及 ID：`kr-ai-python-implementation`
- 当前内容：`must_have/high`；标题只写 Python，描述允许 Python 或等价语言。
- Codex 建议：保留 `must_have/high`，标题修订为“使用 Python 或等价语言实现可运行的 AI 应用组件”，使标题与描述一致且避免把具体语言误写成唯一实现方式。
- 可选项：保留类型并改标题 / 原样保留 / 降为 `responsibility/high`。
- 影响：只改标题不改变岗位实质；降级会使首版画像更技术中立，但弱化可运行工程实现的基础定位。
- 用户选择：采用 Codex 建议：保留 `must_have/high`，标题改为“使用 Python 或等价语言实现可运行的 AI 应用组件”。

### D-04 模型或 AI 服务集成类型

- 涉及 ID：`kr-ai-model-api-integration`
- 当前内容：`must_have/high`，标题强调 API。
- Codex 建议：改为 `responsibility/high`；两个独立来源支持其重要性，但 API 是常见实现路径，不应成为所有 AI 应用实习岗位的隐性准入门槛。
- 可选项：改为 `responsibility/high` / 保留 `must_have/high` / 改为 `preferred/medium`。
- 影响：降为 responsibility 不改变知识检索或评分，只降低公开知识被误解为硬门槛的风险。
- 用户选择：采用 Codex 建议：改为 `responsibility/high`。

### D-05 输出调试能力类型

- 涉及 ID：`kr-ai-output-debugging`
- 当前内容：`must_have/high`。
- Codex 建议：改为 `responsibility/high`；复现、隔离和回归验证是核心工作职责，但来源更直接支持“需要执行”而非“未具备即不具资格”。
- 可选项：改为 `responsibility/high` / 保留 `must_have/high` / 改为 `preferred/medium`。
- 影响：保留 high 可维持核心地位；类型降级可避免和当前 JD 的真正 must-have 混淆。
- 用户选择：采用 Codex 建议：改为 `responsibility/high`。

### D-06 隐私、安全与数据边界类型

- 涉及 ID：`kr-ai-privacy-security`
- 当前内容：`must_have/high`。
- Codex 建议：改为 `responsibility/high`；NIST 与应用框架足以支持其高重要度，但知识库不应把一般安全责任自动表达成所有实习岗位的资格门槛。
- 可选项：改为 `responsibility/high` / 保留 `must_have/high` / 改为 `implicit/high`。
- 影响：任何选项都不触发 ScoringEngine 封顶；保留 must-have 会更强调安全底线，但更容易被误读为评分条件。
- 用户选择：采用 Codex 建议：改为 `responsibility/high`。

### D-07 High importance 分层

- 涉及 ID：`kr-ai-agent-workflow`、`kr-ai-project-communication`、`kr-ai-prompt-design`
- 当前内容：三项均为 `high`，全表 15 条中有 12 条 high。
- Codex 建议：三项均降为 `medium`；Agent 不是所有应用任务的默认方案，项目表达是支持性能力，Prompt 设计与保留为 high 的结构化输出存在部分权重重叠。
- 可选项：三项全部降级 / 逐项选择 / 全部保留 high。
- 影响：建议方案形成 high 9、medium 6、critical 0 的更清晰层级，不改变任何候选人评分。
- 用户选择：采用 Codex 建议：三项均降为 `medium`。

### D-08 面试问题难度校准

- 涉及 ID：`iq-ai-evaluation`、`iq-ai-tradeoff`
- 当前内容：前者 `advanced`，后者 `basic`。
- Codex 建议：两者均改为 `medium`；当前评估题是应用层基础评估设计，取舍题则要求基于证据比较方案，均更符合实习生中等难度。
- 可选项：两项均改为 medium / 只调整一项 / 原样保留。
- 影响：只影响知识题目的展示分级，不改变 Generator 最终题量、评分或报告结论。
- 用户选择：采用 Codex 建议：`iq-ai-evaluation` 与 `iq-ai-tradeoff` 均改为 `medium`。

### D-09 来源范围与 Google 日期元数据

- 涉及 ID：全部 7 个 `ks-ai-*` 来源，重点为 `ks-ai-google-managing-ml-projects`
- 当前内容：来源均为 pending；Google 的 `published_at` 使用页面“最后更新”日期 `2025-08-25`。

- 可选项：接受限定用途并清空 Google `published_at` / 接受并保留当前日期 / 要求重新核验指定来源。
- 影响：日期调整会改变 canonical content hash；不影响来源主体、知识语义或许可说明。
- 用户选择：采用 Codex 建议：接受 7 个来源的限定用途；Google `published_at` 改为 `null`，最后更新日仅保留在审核记录中。
